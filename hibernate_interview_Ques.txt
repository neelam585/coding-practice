EmployeeId (Composite Key Class)
@Embeddable
public class EmployeeId implements Serializable {

    private String name;
    private String gender;

    public EmployeeId() {
    }

    public EmployeeId(String name, String gender) {
        this.name = name;
        this.gender = gender;
    }

    // getters and setters

    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (!(o instanceof EmployeeId)) return false;
        EmployeeId that = (EmployeeId) o;
        return Objects.equals(name, that.name)
                && Objects.equals(gender, that.gender);
    }

    @Override
    public int hashCode() {
        return Objects.hash(name, gender);
    }
}

In Java Persistence API / Hibernate ORM, lazy-loaded data means:

Data that is not fetched from the database immediately when the parent object is loaded.

It is loaded only when you actually use it.

Example

Suppose you have:

@Entity
class User {

    @Id
    private Long id;

    private String name;

    @OneToMany(fetch = FetchType.LAZY)
    private List<Order> orders;
}

Here:

fetch = FetchType.LAZY

means:

User data loads immediately
orders data does NOT load immediately
What happens internally?

When you do:

User user = entityManager.find(User.class, 1L);

Hibernate fetches only:

id, name

NOT orders.

orders is kept as a proxy object (placeholder).

When actual data loads?

Only when you access it:

user.getOrders();

At that moment Hibernate fires another SQL query.

This is called Lazy Loading.

Why LazyInitializationException occurs

Example:

Session session = sessionFactory.openSession();

User user = session.get(User.class, 1L);

session.close(); // session closed

user.getOrders(); // ERROR

Now Hibernate wants to load orders,
BUT database session is already closed.

So it throws:

LazyInitializationException
Simple Real-Life Analogy

Imagine:

You ordered a book online
Only book cover arrives first
Inside pages download later when opened

If internet disconnects before opening:
→ pages cannot load

Same concept in lazy loading.

EAGER vs LAZY
Type	Behavior
EAGER	Load immediately
LAZY	Load only when needed
Common places where LAZY is used

Mostly with relationships:

@OneToMany
@ManyToMany
@ManyToOne
@OneToOne
How to avoid LazyInitializationException
1. Access data before session closes
user.getOrders().size();
2. Use JOIN FETCH
@Query("SELECT u FROM User u JOIN FETCH u.orders")
3. Use DTO Projection

Best approach in production.

4. Change to EAGER (not usually recommended)
fetch = FetchType.EAGER

Can cause performance issues.
